# dsptchr

**dsptchr** (say "dispatcher") is a self-hosted personal orchestrator. It watches your mail, calendars, repositories and servers, tells you in Telegram only what is new or matters, keeps your todos and reminders, and answers questions about all of it. Anything it does goes through a deterministic gate first.

> Personal project, built for one operator. No support, no roadmap promises.

## Design rules

1. Whoever reads untrusted content can't act. Mail, issue titles and server output go to tool-less readers or straight to you, never into the model that decides.
2. Whoever decides can't execute. The orchestrator model only proposes; deterministic code executes.
3. Deterministic rules check every action: a policy per action type, rate limits, a daily model budget and a kill switch.

Details: [`docs/security.md`](docs/security.md), [`docs/architecture.md`](docs/architecture.md), decision log in [`docs/decisions.md`](docs/decisions.md).

## What it does

- **Todos and reminders.** Write "call the bank tomorrow at 9" in Telegram or mail it to a `+todo` address. Reminders arrive with Done, +1 h and Tomorrow buttons.
- **Briefings.** Morning and evening, with today's events, birthdays, mail worth reading, open findings and GitHub activity.
- **Questions.** "What do I have tomorrow?", "When was I at the garage?", "Is CI green everywhere?" The orchestrator reads state through narrow tools and answers.
- **Watchers.** Server health (wraps your existing check script), GitHub (PRs, issues, CI), mail and calendar via Proton, calendar and contact birthdays via iCloud CalDAV/CardDAV.
- **Knowledge.** Search, read and extend your own notes through an adapter you provide ([`docs/knowledge.md`](docs/knowledge.md)).
- **Receipts.** Every reply lists the changes that really happened, generated by code, not by the model.
- **Commands.** `/todos`, `/calendar`, `/mail`, `/health`, `/github`, `/status`; `stop` pauses everything, `start` resumes.

## Requirements

- macOS with Node 24 and pnpm (secrets live in the macOS Keychain; the daemon runs as a LaunchAgent)
- A Telegram bot and a group, an Anthropic API key with a spend limit
- Optional, per watcher: a fine-grained read-only GitHub token, [`proton-cli`](https://github.com/roman-16/proton-cli) pinned to a verified release, an iCloud app-specific password, a server health script that prints JSON, a push monitor URL for the heartbeat

## Setup

```sh
pnpm install          # also installs the git hooks (gitleaks and a private-terms denylist)
pnpm test && pnpm check
```

1. Copy [`examples/private/`](examples/private/) to `~/.config/dsptchr/private/` and fill in the placeholders.
2. Store every secret in the Keychain, for example `security add-generic-password -s dsptchr.private -a telegram-bot -w`. Instance files only reference them.
3. Run `node packages/daemon/src/main.ts --instance private`, or install [`examples/launchd/`](examples/launchd/) as a LaunchAgent.

Instance data (config, state, rules, secrets) never lives in this repository.

## Development

- TypeScript, strict, no build step: Node runs the sources directly.
- Test first. `pnpm test` runs unit, contract and the deterministic part of the injection suite; `pnpm test:injection` adds live model cases (needs the API key, costs a few cents).
- Changes to `packages/gate`, `packages/executor` and policy files widen what the orchestrator may do; see [`AGENTS.md`](AGENTS.md).
